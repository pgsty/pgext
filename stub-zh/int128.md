`int128` 为 PostgreSQL 17–19 添加有符号 128 位整数类型。1.0 版用 16 字节保存 -2^127 至 2^127-1 的值，并提供带溢出检查的算术、转换、聚合与索引支持。这是定宽整数，并非任意精度数值。

### 保存和查询大整数

由超级用户安装扩展。它可迁移模式，不需要共享预加载或重启。

```sql
CREATE EXTENSION int128;
CREATE TABLE ledger (id int128 PRIMARY KEY, amount int128 NOT NULL);
INSERT INTO ledger VALUES ('500000000000000000000'::int128, 100::int128);
SELECT * FROM ledger WHERE id = '500000000000000000000'::int128;
SELECT sum(amount), avg(amount) FROM ledger;
```

超出普通整数范围的字面量应显式转换为 `int128`，否则 PostgreSQL 可能选择无法使用整数索引的 numeric 比较。算术溢出和超出范围的类型转换都会报错。整数除法向零截断；numeric 转换的中点值向远离零的方向舍入，浮点转换则遵循服务器的中点取偶数规则。

### 对象与索引

该类型提供算术、比较和位运算操作符，以及 `abs()`、`div()`、`mod()`、`gcd()`、`lcm()`、数学函数和 `generate_series()`。`sum()` 聚合返回 int128，仍然检查溢出；`avg()` 返回精确 numeric。扩展还提供统计、最小值/最大值和位运算聚合。

Btree 与 hash 支持常规相等和排序操作；GiST 与 SP-GiST 支持范围条件和 KNN 排序；扩展也包含 GIN 与 BRIN 操作符类。GIN 范围扫描不具备良好的选择性，且不支持不等操作符。GiST/SP-GiST 的 KNN 距离使用双精度浮点数，超过 2^53 后会损失整数精度。

```sql
SELECT '[1,10)'::int128range @> 5::int128;
SELECT '{[1,10)}'::int128multirange;
```

`int128range` 和 `int128multirange` 用于范围操作。该类型没有类型修饰符。JSON 转换会将此自定义类型输出为字符串；需要 JSON 数值时，应转换为 `numeric`。如果数值适合 bigint，通常使用 bigint 会节省存储与处理开销。更宽的类型本身不构成性能保证。
