# PGEXT 1.8.0

PGEXT 1.8 introduces native commands for bilingual documentation and GitHub
metadata, consolidates builder repository management, and moves the public
Hugo catalog to its own checkout. The embedded Go web app and JSON API still
ship with the CLI.

## Upgrade

- `pgext env repo` is an alias for `pgext repo set`. Use `pgext repo list`,
  `add`, `rm`, `status`, and `update` for individual actions. On an existing
  builder, preview migration with `pgext repo set pgdg pigsty --replace --plan`.
  The migration backs up conflicting PGDG and Pigsty definitions and preserves
  unrelated sources. PGDG APT defaults to HTTPS, and both suppliers use
  bundled signing keys for APT and RPM.
- `pgext doc load --dry-run` validates the complete bilingual corpus in a
  rolled-back transaction. Use `pgext doc load` to apply it and `pgext doc dump`
  to export. The `bin/load-stub` and `bin/dump-stub` wrappers default to their
  own source checkout. `pgext gen lint --pair` checks bilingual stub pairs.
- `pgext sync github` refreshes the repository cache by default. Add
  `--backfill` to apply metrics from repositories successfully fetched in the
  current run. A cache-only backfill requires `--backfill-only --refresh-after`
  with an RFC 3339 timestamp.
- Scripts using `pgext env proxy` should configure the build environment's
  `HTTP_PROXY` and `HTTPS_PROXY` directly.
- `pgext gen site` writes the Hugo catalog to the
  [pgext.cloud site checkout](https://github.com/pgsty/pgext.cloud). Use
  `-D` or `PGEXT_SITE_DIR` to set the destination.

## API and build fixes

- Matrix, file, and changelog responses identify the requested extension
  even when it shares a package with another extension. The web app keeps
  the global matrix in memory and derives it from the live package tables.
- The extension API uses the Universe field names. Migrate `state` to
  `packaged`, `source` to `tarball`, `ext_type` to `kind`, `ext_kernel` to
  `kernel`, `ext_vendor` to `vendor`, `require_by` to `required_by`, and
  `last_update` to `last_active`. Use `stars`, `watchers`, and `forks` for
  activity counts, and the top-level URL fields for links formerly in
  `doc_links`.
- RPM builds stage and fingerprint the spec's local inputs, including
  PDU's PostgreSQL license file.
- The bundled catalog contains 2,844 extensions, including 628 in the
  packaged catalog.

## Optional legacy matrix cleanup

Fresh PGEXT databases omit the legacy `pgext.matrix` materialized view.
Existing standalone databases can upgrade in place. The CLI, server, and
site generator use `pgext.pkg`, and the upgrade leaves existing database
objects in place.

After confirming the database identity and checking for direct SQL readers,
back up the view definition before running the
[optional cleanup SQL](https://github.com/pgsty/pgext/blob/v1.8.0/db/drop-legacy-matrix.sql) from the source checkout.

```sh
pg_dump --schema-only --strict-names --table=pgext.matrix "$PGURL" > pgext-matrix-before-1.8.sql
psql "$PGURL" -X -v ON_ERROR_STOP=1 -f db/drop-legacy-matrix.sql
```

The script uses a short lock timeout and rejects dependent objects.
For rollback, restore the saved definition and refresh the materialized view.
Keep the view on databases that participate in PG.CENTER's complete native
PGEXT snapshots, which require the relation on the source and destination.
