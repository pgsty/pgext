# 01 · 愿景与定位

> pgext.cloud：PostgreSQL 扩展宇宙的门户。
> **找到 → 评估 → 安装，三十秒完成。**

## 为什么值得重做

PostgreSQL 最大的护城河是扩展生态，但这个生态的信息入口是分散且破碎的：

| 现有入口 | 问题 |
|---|---|
| PGXN | 只覆盖源码分发，元数据老旧，无包安装信息，无可用性矩阵 |
| pgt.dev (Trunk) | 项目基本停滞 |
| database.dev (dbdev) | 只做 TLE，覆盖面窄 |
| 各云厂商文档 | 各自为政，只列自家支持的扩展，无横向对比 |
| awesome-postgres | 人肉列表，无结构化数据，无安装信息 |
| apt/yum 仓库 | 有包但完全不可浏览、不可搜索 |

**没有任何一个站点能回答这类日常问题：**
- "PG 里做向量检索有哪些选择？哪个还在活跃维护？"
- "timescaledb 在 Ubuntu 24.04 ARM + PG 18 上有包吗？包名是什么？"
- "阿里云 RDS PG 上有哪些独有扩展？"
- "postgis 装完还依赖什么？有哪些扩展依赖它？"

而 pgext 的数据库**已经能回答所有这些问题**——缺的只是一个配得上这份数据的呈现层。

## 数据资产盘点（as-is，2026-07）

这是设计的地基，也是别人抄不走的东西：

| 资产 | 规模 | 说明 |
|---|---|---|
| `universe` | **1,633** 个扩展 | 全宇宙目录：打包 531 + 源码未打包 + 云厂商专有 |
| `extension` | 531 个 | 打包基线（PGDG 114 / PIGSTY 295 / CONTRIB 71 / MIXED 51） |
| `doc` | 531 × 2 语言 | **双语用法文档**，最长 2 万字符，人工撰写 |
| `gh_repo` | 1,342 仓库 | stars / forks / 最近 commit / 最近 release，覆盖 87% |
| `pkg` | 30,720 行 | 可用性矩阵：5 个 PG 大版本 × 16 个活跃 OS 目标 |
| `category` | 16 类 | 带双语描述和图标的功能分类 |
| 关系图 | requires / require_by / see_also | 人工策展的依赖与关联关系 |
| 云厂商 | 91 个专有扩展 | Alibaba 28 / AWS 18 / Tencent 15 / Google 6 / Microsoft 3 … |
| 中文覆盖 | `zh_desc` 95% | 1,547 / 1,633 有中文描述 |

**关键发现**：531 篇中文用法文档已入库（`doc.zh_doc`），但当前 Hugo 站点
`content/e/` 下只有一个 `_index.zh.md`——**中文详情页今天根本没有发布**。
新架构上线即解锁这批存量内容，中文页面数量从个位数跳到 500+。

## 差异化价值主张

四件事，全球范围内只有我们同时做到：

1. **可用性矩阵**：扩展 × PG 版本 × OS/架构 × 仓库，每日更新，精确到包名和版本；
2. **安装闭环**：每个扩展给出 `pig` / `apt` / `dnf` / `CREATE EXTENSION` 的可复制命令；
3. **双语目录**：描述 + 长文档中英文对照，全球唯一的中文 PG 扩展知识库；
4. **全宇宙视野**：不止"我们打包了什么"，还包括源码级、云厂商专有的完整地图。

## 三类用户

| Persona | 典型问题 | 关键页面 |
|---|---|---|
| **解决问题的开发者** | "怎么在 PG 里做 X？" | 搜索 → 详情页 → 复制安装命令 |
| **选型评估的 DBA / 架构师** | "这个扩展在我的环境里能用吗？靠谱吗？" | 可用性矩阵、GitHub 活跃度、依赖关系、同类替代 |
| **生态观察者 / 扩展作者** | "生态全景什么样？我的扩展被收录了吗？" | 宇宙视图、统计、榜单、README badge |

## 北极星指标

**"搜索 → 复制安装命令"的转化次数**（新站自带访问统计，天然可测）。

辅助指标：SEO 自然流量、`/e/` 详情页停留、中文页面流量占比、API/MCP 调用量。

## 叙事：Cloud 与 Universe 是同一个双关

域名 `pgext.cloud` 本身就是题眼——"云"既是 point cloud（扩展点云 / 星云），
也是 cloud（云厂商可用性）。旧站导航里已有 `/galaxy`（扩展宇宙）占位，
新站把它升格为首页的核心体验：

> **英文**：The PostgreSQL Extension Universe
> **中文**：PG 扩展宇宙

首页不是项目介绍，而是宇宙本身（详见 [05 · 设计语言](05-design-language.md)）。

## 自指的彩蛋（吃自己的狗粮）

这个网站由 PostgreSQL 驱动，而且由**它自己收录的扩展**驱动：
`pg_trgm` 做模糊搜索、（P3）`pgvector` 做语义搜索、`pg_stat_statements` 做观测。
页脚放一行徽章："Powered by PostgreSQL 18 + 6 of the extensions it catalogs."
——这是最有说服力的产品演示。
